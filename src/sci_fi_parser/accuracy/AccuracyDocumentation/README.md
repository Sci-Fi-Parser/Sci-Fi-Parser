# Accuracy layer — junior dev guide

Welcome. If you're new to this codebase, or new to working with vision-
language models, or just want a gentler walkthrough than the
[../README.md](../README.md), start here.

These docs mirror the senior ones one-for-one. Each file is the same topic,
just slower, with definitions and worked examples.

## What is the "accuracy layer"?

Our project, `sci_fi_parser`, reads scientific charts from documents and
turns them into structured data (numbers, categories, axes). That's a hard
problem — there are lots of ways to do it (a vision model, an OCR pipeline,
a chart-specialised model), and we need a way to decide which one is
actually working well.

The **accuracy layer** is that "way to decide". Specifically:

1. We **generate** fake charts where we already know the right answer
   (because *we* drew them).
2. We **run** any chart-reader (which we call an "extractor") on those
   fake charts.
3. We **score** what it returned against what we know is true, and write a
   nice HTML report.

That's it. Three layers — a generator, a scorer, and a shared shape for
the data that flows between them.

## Glossary (read this first)

These terms will come up over and over. If you forget what one means,
come back here.

| Term | What it means here |
|---|---|
| **Chart** | An image of a bar chart, line chart, etc. The thing we want to read. |
| **Ground truth** | The "real" answer. For our synthetic charts, it's the values we plotted. |
| **Extractor** | A piece of code that takes a chart image and returns numbers. Could be a VLM, an OCR pipeline, or anything else. They all look the same from outside. |
| **VLM** | "Vision-Language Model" — an AI model that understands both images and text. We use it as one kind of extractor. |
| **OCR** | "Optical Character Recognition" — software that reads text from images. Used for axis labels, not for reading bar heights. |
| **Ollama** | A local program that runs LLM and VLM models on your own machine. We talk to it via its Python library. |
| **Benchmark** | The whole "run an extractor over many charts and score it" process. |
| **Pipeline** | The full path from a document going in to data coming out. The accuracy layer doesn't *do* extraction; it *evaluates* extractors. |
| **Schema** | A description of what shape the data has — what fields exist, what types they are. We have one schema everyone agrees on (`ChartData`). |
| **Pydantic** | A Python library that validates data against a schema at runtime. If you ask for an `int` and get a `str`, pydantic raises an error. |
| **Protocol** | A Python type-hint pattern that says "any class with this method counts as this type." Like a duck-typing contract that the type checker understands. |
| **Dataclass** | A short way to write a Python class that's basically a struct (just fields, with auto-generated `__init__` etc.). |
| **TOML** | A config file format (like `.ini` but better). We use it for files in `config/`. |
| **CLI** | "Command Line Interface" — a program you run from the terminal, with flags like `--data ...`. |
| **HTML report** | A self-contained `.html` file you can open in any browser. No server needed. |
| **`ChartData`** | The pydantic class every extractor returns. The "shared shape." |
| **`Extractor` (capital E)** | The Python protocol that defines what an extractor must look like (a `name` and an `extract(image_path)` method). |
| **Synthetic data** | Fake data, generated by us. The opposite of "real data" (scraped from documents). |
| **Density** | How many bars a chart has. More bars = harder to read = "higher density". |
| **`labels.jsonl`** | A JSON-lines file (one JSON object per line) that lists the ground truth for every chart in a dataset. |

If you're still confused after reading, ask. The list grows. Add to it.

## Two rules the code enforces (don't break them)

If you change anything in this layer and a test starts failing, it's
probably one of these. They're enforced by `tests/test_smoke.py`.

1. **`schema.py` must stay lightweight.** It cannot import `matplotlib`,
   `cv2`, or `ollama`. Why: importing matplotlib takes about a second.
   Other parts of the codebase need to read `ChartData` without paying
   that cost.

2. **`accuracy/__init__.py` must not pull in matplotlib (even indirectly).**
   Same idea — importing `sci_fi_parser.accuracy.benchmark` shouldn't drag
   matplotlib in just because synthetic chart generation also lives in
   the same package.

If you don't understand why these rules exist yet, that's fine. Read
[Decisions.md](Decisions.md) entries #4 and #5 when you do.

## Where to look in the code

If you want to read the actual code, here's the smallest possible map:

```
src/sci_fi_parser/
  schema.py                ← read this first. It's small. It's the contract.
  accuracy/
    benchmark.py           ← the scorer + HTML report
    vlm.py                 ← talks to ollama
    vlm_config.py          ← loads the VLM TOML config
    synthetic/             ← the chart generator (one file per concern)
      cli.py               ← the command-line entry
      config.py            ← which charts to generate
      style.py             ← randomised look
      render.py            ← actually draws the chart
      generate.py          ← the three modes (series / random / preview)
      output.py            ← post-processing (augment, overlay, sqlite)
```

Each of those files has a docstring at the top explaining what it's for.
That's a good way to navigate — start at `schema.py`, follow imports.
